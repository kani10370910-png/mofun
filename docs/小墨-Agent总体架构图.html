3. Harness 四层解剖（核心）

对齐「Agent 不是模型，是 harness」：A 装配 / B 推理委托 / C 调度 / D 边界。

flowchart LR
  subgraph A["A 上下文装配"]
    SOUL[SOUL 人设]
    AGENTS[AGENTS 硬规约]
    TOOLS[TOOLS 工具表]
    CTX[当前专家槽表 · Skill]
    VOL[本轮用户句 · 已填槽 · 品牌片段]
  end

  subgraph B["B 模型推理"]
    NOTE[编排决策在代码
不自研服务端 turn loop]
    LLM[委托 collectGenerate
扩写 / 提案文案]
  end

  subgraph C["C 工具调度"]
    REG[tools/registry]
    TP[toolPropose]
    TG[toolGenerate]
    TM[memory_read/write]
  end

  subgraph D["D 执行边界"]
    G1[assertCanPropose]
    G2[assertCanGenerate]
    G3[failureRetryActions]
    G4[缺参考图硬拦截]
  end

  A --> B
  B --> C
  D --> C
  C --> OUT["/api/* 结果回写 UI"]

A · 装配原则

  • stable：人设 + 安全规约 + 工具表
  • context：仅当前 Specialist，不预加载全书
  • volatile：本轮可变，每轮重建

D · 边界原则

  • 能用 hook 别用 prompt
  • 视觉类未确认 → 禁止出图
  • 失败固定重试卡，禁止假装成功

5. 运行时主链路（一轮对话）

sequenceDiagram
  participant U as 用户
  participant HV as HomeView
  participant L as runAgentTurn
  participant A as assembleContext
  participant S as specialists/skills
  participant G as gates
  participant T as tools/registry
  participant E as execute
  participant API as /api/generate|image
  participant M as memory

  U->>HV: 输入文本 / 点选行动卡
  HV->>L: runAgentTurn({text, state, action})
  L->>A: 装配上下文
  L->>M: injectMemorySlots
  alt 自由文本
    L->>L: resolveIntentEveryTurn
    L->>S: getSpecialist / switch
    L->>L: 抽槽 / 双问 / planned|ready
    L-->>HV: AssistantTurn
    HV-->>U: 气泡 + 双问/策划/出口
  else propose / confirm_plan / generate / extend_vi
    L-->>HV: 「正在调用…」占位
    HV->>T: executePropose / executeGenerate
    T->>G: assertCan*
    alt 闸门拒绝
      G-->>HV: error + failureRetryActions
      HV-->>U: 重试卡
    else 通过
      T->>E: 真实执行
      E->>API: fetch
      API-->>E: 文本/图片
      E-->>HV: ExecuteResult
      HV->>M: persistSlotsToMemory（确认时）
      HV-->>U: 交付 + 建议栈 / 灯箱
    end
  end

8. 工具目录与闸门规则

ToolRegistry（≤ 精简集）

  • propose → /api/generate 提案场景
  • generate → generate + /api/image
  • memory_read → 读品牌记忆
  • memory_write → 写品牌事实

D 闸门拒绝码

  • no_specialist — 未识别方向
  • plan_unconfirmed — 视觉未确认策划
  • missing_ref_image — 商拍/IP扩展缺图

action.kind 全量（UI 合同）

option · defaults · category · propose · generate · confirm_plan · revise_plan · pick_proposal · change_direction · adjust_colors · extend_vi · handoff（仅 toast，不跳转）

10. 范围：已落地 vs 明确不做（本阶段）

已落地

  • 客户端 Harness 四层
  • 每句意图 + 同组双问
  • 方向策划确认闸门
  • 真实 propose / generate
  • 品牌记忆 + 会话历史
  • 出图后建议栈（VI/换向/配色）
  • 对话内完成，不强制跳转

本阶段不做 / 边界外

  • 服务端统一 Agent 循环 API
  • 改 Studio 等功能页
  • 统一无限画布
  • MCP / 自演化 Skill
  • 多租户 IM 通道
  • Lead/Worker 多模型分工（可后置）
