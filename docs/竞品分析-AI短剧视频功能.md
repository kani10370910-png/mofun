## 一、赛道背景

2025 年底至 2026 年初,AI 短剧/漫剧从"单镜头生成工具"进入**全流程工业化生产**阶段。三个标志性事件:

1. **360 纳米漫剧流水线**(2026-01-29 上线):国内首个自称"工业级"的 AI 漫剧智能体生产平台,提出"视频世界模型 + 三大记忆"解决一致性;
2. **有戏AI**(2026-01 上线):上线首月折算 ARR 3600 万元、5 天 1.3 万创作者注册,验证了"一站式剧本→成片"的付费意愿;
3. **火宝短剧**(GitHub 1.2 万 Star):开源(Apache-2.0)拉低门槛,把"一句话→完整短剧"做成可自部署的基础设施。

三家分别代表三种路线:**大厂工业化(纳米)、垂直 SaaS 商业化(有戏)、开源自部署(火宝)**。行业共识的核心痛点排序:①跨镜一致性(角色崩坏)②生成成功率(抽卡)③配音出戏 ④流程割裂(工具间来回倒素材)。

## 三、视频生产全流程逐环节对比

### 3.1 流程总览

三家流程高度趋同,都是「剧本 → 资产(角色/场景)→ 分镜 → 逐镜生成 → 合成导出」五段式:

| 环节 | 纳米AI | 有戏AI | 火宝短剧 | 魔方智绘·制作大片(现状) |
|---|---|---|---|---|
| 剧本 | 创建/导入剧本,自动解析角色/场景/情节 | **5 万字超长剧本导入**,自动拆集(每集≤3000 字) | 一句话/梗概 → AI 生成剧本 → 审阅修改 | 需求→原始创意→镜头摘要→完整镜头(三阶生成),支持 txt/docx 上传 |
| 资产 | 上传图片或文字定义角色,保证跨场景一致 | **主体生成模块**:参考图+生图模型出定妆照,存入资产库 | AI 按剧本生成角色肖像,批量创建+自定义上传 | ② 场景/角色/道具,AI 生成/上传/仓库选图参考图 |
| 分镜 | **自动生成完整分镜方案(时长/景别/机位/动作/台词),全部可手调** | 故事板界面自动排好分镜,默认镜头类型可手调 | 分镜自动拆解,支持**首帧/关键帧/尾帧多帧类型** | ③ 分镜脚本:画面描述/字幕/运镜/景别/时长/出镜元素,可排序/锁定 |
| 逐镜生成 | 动态合成自动处理(专属视频世界模型) | **先批量生成分镜图片,再批量图生视频**(两段式) | 分镜→动态视频,文生+图生视频 | ④ 逐镜/批量真实视频生成(Seedance 2.0),真实尾帧无缝衔接 |
| 合成导出 | 自动合成,上传配音自动对口型+字幕 | 台词对齐时间轴+BGM→合成预览;**导出 MP4/剪映工程/独立音轨** | FFmpeg 合成:智能转场/BGM/音效/音画同步,多格式输出 | ⑤ 预览+时间轴字幕,导出成片/剪映素材包/SRT |

### 3.2 关键差异点解读

**① 分镜"图片先行"还是"视频直出"**
- 有戏AI 采用**图片先行两段式**:先批量生成每个分镜的静态图(便宜、快、可反复抽),用户确认构图/角色后再批量图生视频。这把最贵的"视频抽卡"成本压到了确认之后,是**成功率经济学**上的最优解。
- 火宝用"首帧/关键帧/尾帧多帧类型"达到类似效果(帧先确认、再生视频)。
- 纳米靠"视频世界模型"直接把成功率做到 90%,思路是**模型层解决**而非流程层规避。
- **制作大片现状**:直接逐镜出视频(单镜 3–4 分钟、失败重试),更接近"视频直出"。智能多帧/首尾帧模式部分具备"帧先行"能力,但没有"先批量出图确认、再批量出视频"的标准动线。

**② 一致性机制的三种实现**
- **纳米(模型层)**:专属"视频世界模型",构建"三维场景+一维时间线"四维空间,三大记忆——空间记忆(场景布局/机位一致)、资产记忆(角色道具跨镜统一)、视觉记忆(色彩/光线/风格连贯)。这是三家中唯一宣称在**模型内部**维护跨镜状态的。
- **有戏(资产层)**:定妆照存入资产库,逐镜生成时引用主体资产,靠"资产引用+图片先行确认"锁定。
- **火宝(帧链层)**:统一视觉风格提示+关键帧衔接。
- **制作大片现状**:参考图注入(reference_image)+ 真实尾帧衔接 + 提示词硬约束(锁脸/锁风格),属于"资产层+帧链层"混合,与有戏同层,弱于纳米的模型层记忆(受制于第三方模型,无法自研世界模型)。

**③ 批量与效率**
- 纳米:30 分钟超长视频生成能力,单集 30–60 分钟产出,流水线模式全自动;
- 有戏:批量提交后台跑任务(图批量→视频批量),一人一天一部;
- 火宝:端到端全自动,批量生产多部;
- **制作大片现状**:批量生成为**串行**(为保尾帧衔接必须逐镜等待),10 镜 ≈ 30–40 分钟,与纳米单集时长相当,但无后台任务队列——离开页面依赖会话单例,不能关机跑。

**④ 编辑与控制粒度**
- 纳米:「流水线推进 + 智能画布调整」双模式——快速量产走全自动,精品走关键节点人工干预;分镜的时长/景别/机位/动作/台词全可手调;
- 有戏:故事板逐镜调整镜头类型,情绪/语速分镜级;
- 火宝:预览调整+配置参数,粒度最粗;
- **制作大片现状**:③ 的控制粒度(运镜/景别/时长/出镜元素/锁定)已与纳米对齐,加上"编辑视频(v2v 局部修改)""重生成两头无缝"两项**三家都没有**的特色能力。

**⑤ 声音与口型**(承接上一份声音专题)
- 纳米:上传/录制配音→自动**口型驱动**+自动字幕(音色库规划中);
- 有戏:300+ 音色自动匹配、情绪参数、0.1s 字幕对齐;
- 火宝:配音/BGM/音效埋在自动合成里;
- **制作大片现状**:声音由 Seedance `generate_audio` 直出(音色不可控),`/api/tts` 音色链路已建但未接入 Studio(方案已定,见 PRD)。

**⑥ 导出生态**
- 有戏最完整:MP4 + **剪映工程文件** + 独立音轨,横竖屏多格式;
- 火宝:FFmpeg 服务端合成,多格式;
- 纳米:平台内成片;
- **制作大片现状**:MP4/WebM(浏览器 MediaRecorder)+ 剪映素材包(zip)+ SRT。浏览器端合成受 MediaRecorder 限制(编码质量/格式弱于服务端 FFmpeg),且"剪映素材包"是裸素材 zip,不是可直接打开的剪映工程。

## 四、逐家深度分析

### 4.1 纳米AI漫剧流水线——"模型层工业化"路线

**核心主张**:把漫剧生产做成流水线工厂,用自研"视频世界模型"从模型层面解决一致性与成功率。

**视频能力细节**
- 剧本解析自动识别角色/场景/情节要素;
- 资产生成:图片或文字定义角色,跨场景外观一致;
- 分镜:自动产出含镜头时长、景别、机位、动作、台词的完整方案,全要素可手调;
- 动态合成:后续环节全自动;支持 30 分钟超长视频;
- 一致性:四维影视空间(3D 场景+时间线)+空间/资产/视觉三大记忆;
- 效率:单集 30–60 分钟、素材成功率 90%(vs 行业 15%)、效率 3 倍+;
- 生态:开放**私有智能体接入**,工作室可注入自有视觉风格;
- 交互:流水线(全自动)/专业(节点干预)双模式。

**优势**:成功率与一致性的技术天花板最高;超长时长;大厂算力与分发(360 系流量)。
**短板**:聚焦"漫剧"(动画感)而非真人感短剧;声音模块尚弱(音色库"规划中",依赖用户上传配音);收费未定,平台锁定风险。
**一句话评价**:重资产的"卖水人"打法——把最难的模型层问题内部消化,换取工作室级客户。

### 4.2 有戏AI——"流程层商业化"路线

**核心主张**:把散落在 N 个工具里的短剧流程装进一个 Agent 编排系统,一个人一天出一部。

**视频能力细节**
- 剧本:5 万字导入,自动拆集(每集≤3000 字);
- 资产:主体生成模块——参考图+可选生图模型出**定妆照**,入资产库,后续所有分镜引用(一致性的锚);
- 分镜:故事板自动排镜,默认景别(中/近/特写)可调;
- 生成:**先批量出分镜图 → 确认 → 再批量图生视频**,后台任务队列;
- 声音:300+ 音色自动匹配/情绪参数/0.1s 对齐(详见声音专题);
- 合成:台词时间轴+BGM→合成预览;
- 导出:MP4 / **剪映工程** / 独立音轨,抖音竖屏/B站横屏多格式;
- 效率:15 天 → 1–2 天(5–10 倍)。

**优势**:流程完成度和商业验证最强(ARR 3600 万/首月);"图片先行"动线对成本与成功率的平衡最聪明;声音是三家最强;导出生态贴创作者习惯。
**短板**:模型层无自研壁垒(拼装第三方模型),一致性依赖资产引用,长片/复杂运镜上限受限;订阅+算力成本对重度用户不低。
**一句话评价**:产品经理式的胜利——不解决最难的问题,把"次难但高频"的流程问题全解决了。

### 4.3 火宝短剧——"开源基建"路线

**核心主张**:一句话生成完整短剧,全流程开源可自部署、可二开。

**视频能力细节**
- 流程:项目创建(标题/类型/风格/时长/比例)→ 剧本生成(梗概→AI→审阅→角色→场景)→ 视频生成(分镜→预览调整→配置参数→合成)→ 成品输出;
- 模型接入:OpenAI/Gemini/豆包等主流 API + **Ollama 本地模型**,支持冗余与故障转移;
- 分镜:首帧/关键帧/尾帧多帧类型,统一视觉风格;
- 合成:服务端 **FFmpeg**——智能转场、BGM/音效、音画同步、多格式输出;
- 技术栈:Go + Vue3/TS(另一信源称 Nuxt3+Hono+Mastra Agents),DDD 微服务,Docker/云一键部署;
- License:Apache-2.0。

**优势**:零许可成本、数据私有、可深度二开;模型可插拔(含本地模型);服务端 FFmpeg 合成质量高于浏览器端方案。
**短板**:产品打磨最浅(声音/编辑粒度/一致性均无深耕);无 SLA,能力上限=接入模型的上限;面向开发者,非创作者开箱即用。
**一句话评价**:不是竞品,是"毛坯房图纸"——对我们更有价值的是**参考其架构**(任务队列、FFmpeg 服务端合成、模型故障转移),而非担心其抢用户。

## 六、战略解读:三条路线的启示

1. **"成功率经济学"是共同主线**。三家用不同层的手段压"抽卡"成本:纳米在模型层(世界模型 90% 成功率)、有戏在流程层(图片先行)、火宝在架构层(模型冗余切换)。**视频抽卡贵,图片抽卡便宜,确认要前移**——这是对我们最普适的一条。
2. **一致性是购买理由,不是功能点**。三家都把"角色不崩"放进第一屏卖点。我们的"参考图+尾帧链+锁脸"在演示级足够,但缺"定妆照确认"这个**用户可感知的仪式**——有戏把一致性做成了看得见的动线(定妆照入库),用户因此相信它。
3. **后台任务队列是"工业化"的分水岭**。三家都能"提交后离开",我们必须在页面里守着。串行衔接是我们的技术约束(尾帧链),但"服务端队列+完成通知"不与之冲突。
4. **导出生态决定留存**。有戏的"剪映工程"导出击中了创作者真实工作流(AI 出粗片→剪映精修)。我们的素材包 zip 是半成品。

## 七、对「制作大片」的行动建议

### 已领先、要守住(差异化卖点)
- **真实尾帧无缝衔接 + 重生成两头无缝**:三家未见等价能力,是"镜间连贯"的硬差异;
- **编辑视频(v2v 局部修改)**:独有,继续深化(如局部区域涂抹重绘);
- **时间轴字幕编辑**:粒度优于纳米/火宝。

### 优先补齐(按 ROI 排序)
1. **"图片先行"标准动线**(高 ROI):③ 分镜脚本增加"批量生成分镜图→逐镜确认→④ 批量出视频"。生图便宜、确认前移,直接降视频抽卡成本;技术上已有 /api/image 和首帧机制,主要是动线整合。
2. **逐镜 TTS 配音接入**(高 ROI,方案已定):角色→音色自动匹配 + 分镜级台词配音,对齐有戏基础形态;`/api/tts`+`playerAudio` 积木现成。
3. **后台任务队列**(中 ROI,需服务端):生成任务落服务端队列,浏览器可关;顺带解决 localStorage 脆弱性(项目状态服务端化)。
4. **剪映工程导出**(中 ROI):由素材包升级为剪映草稿协议(draft_content.json),贴创作者精修工作流。
5. **服务端 FFmpeg 合成**(低优先):替代 MediaRecorder,提升成片编码质量;可参考火宝的 Go+FFmpeg 实现。

### 可以不追
- 自研视频世界模型(纳米路线):资源量级不匹配,继续借力 Seedance 等第三方模型迭代;
- 口型驱动:数字人模块的事,不进制作大片主线;
- 开源:商业形态不同。
